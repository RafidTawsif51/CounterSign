# Countersign data model

Source: `backend/app/models.py` (SQLModel). This is the reference for the seed script and the risk engine.

Conventions:

- All primary keys are strings with a prefix, generated by `new_id(prefix)` (prefix + 12 hex chars), e.g. `ven_3fa91c02b7d4`. Seed scripts may pass their own IDs for determinism.
- All datetimes are timezone-aware UTC (`utcnow()`). Pass aware datetimes when seeding.
- Enums are stored as plain VARCHAR (not native DB enums). The stored string equals the name below.
- JSON columns are `JSON` (works on SQLite and Postgres).
- Writes to `vendor_bank_accounts` and `vendor_contacts` belong to `services/verify.py` only. The seed script is the one exception, because it builds history.

## Enums

| Enum | Values |
|---|---|
| VendorStatus | active, inactive |
| ContactSource | on_file, website, listing |
| RunStatus | running, completed, failed |
| PaymentStatus | pending, paid, held, blocked |
| Decision | auto_pay, controller_review, hold, hold_and_verify |
| CallOutcome | confirmed, denied, no_answer, unclear |
| AttackSource | console, judge, bounty_email |
| AttackResult | caught, missed |
| ModerationStatus | pending, approved, hidden |
| AuditActor | agent, human, system |

VendorStatus values and the Decision list are my choice because the spec names the fields but not every value. Tell me if you want different ones.

### risk_assessments (`ras_`)

| Field | Type | Notes |
|---|---|---|
| id | str PK | |
| payment_id | str FK payments.id | |
| score | int | 0 to 100, capped |
| decision | Decision | the spec stores the decision in this table (example output); this field holds it |
| hard_rules_fired | JSON list[str] | e.g. `["destination_changed"]` |
| signals_json | JSON list[Signal] | see below |
| model_version | str | |

Signal object inside `signals_json` (Pydantic `Signal` in models.py):

```json
{"name": "bank_details_changed", "weight": 30,
 "detail": "New account ending 7781; last verified ending 2204",
 "evidence_id": "evd_9c1e4a7b02d3"}
```

`evidence_id` is generated by `Signal(...)`. The `/ask` endpoint cites it. Always build signals with the `Signal` model so the id exists.

| Field | Type | Notes |

| Field | Type | Notes |
